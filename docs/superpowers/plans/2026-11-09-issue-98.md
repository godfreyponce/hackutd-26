# Win agent: generalized live status page Implementation Plan (issue #98)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `python3 hackathons/agent/status/collector.py <slug>` runs LAND's live status page for any event. It reads the repo, checkout, port and teammates from `hackathons/events/<slug>/status-config.json`, reads thread files from `hackathons/events/<slug>/threads/`, and writes `status.json` into that event folder.

**Architecture:** This is a copy of `tools/status/collector.py` and `index.html` with the LAND constants replaced by values from one per-event JSON config. The collector serves `index.html` from `hackathons/agent/status/` and `status.json` from the event folder on one port. The page keeps LAND's look, states and colors. It drops the LAND-only parts: the hand-written task list, the countdowns, the "After step 1" list, the fixed hardware/hub/software map columns, and the Rafael section. Two generic parts replace them: a grid of every repo issue and one section per configured teammate.

**Tech Stack:** Python 3 stdlib plus the logged-in `gh` CLI, one static HTML file with inline JS. No new dependency.

**Spec:** issue #98 (`gh issue view 98`) and `~/Developer/docs/superpowers/specs/2026-11-09-hackathon-win-agent-design.md` (event folders are `hackathons/events/<slug>/`, gitignored). Sources copied from: `tools/status/collector.py`, `tools/status/index.html`, `tools/status/README.md`.

## Data flow

```text
hackathons/events/SLUG/status-config.json (new, owner writes, gitignored)
   |  repo, checkout, port, teammates
   v
python3 hackathons/agent/status/collector.py SLUG [--once]   (new)
   |
   +--reads--> gh issue list / gh pr list --repo <repo>       (read-only)
   +--reads--> git fetch / for-each-ref / log / worktree list, run in <checkout>
   +--reads--> hackathons/events/SLUG/threads/*.json           (new location, LAND format unchanged)
   |
   +--writes every 60 s--> hackathons/events/SLUG/status.json  (new, gitignored)
   |
   +--serves http://localhost:<port>
          /             --> hackathons/agent/status/index.html (new, committed)
          /status.json  --> hackathons/events/SLUG/status.json

browser index.html --polls every 10 s--> /status.json

tools/status/*   (unchanged; LAND's page keeps working as before)
```

## Global Constraints

- Leave `tools/status/` exactly as it is. Copy and generalize; do not move it. Do not run LAND's collector (it writes into `tools/status/`).
- Read-only on GitHub: `gh` reads only (`issue list`, `pr list`). `git fetch` is the only network git call.
- No new dependency: stdlib Python plus `gh`.
- Per-event output (`status.json`, `status.json.tmp`, thread files, `status-config.json` with teammate logins) stays in `hackathons/events/<slug>/`, which `.gitignore` already ignores (`hackathons/events/`, committed in #91).
- Nothing LAND-specific in `hackathons/agent/status/`: no `godfreyponce/hackutd-26`, no `rafael`, no `8099`, no `Godfrey`, no fixed issue numbers, no `America/Chicago`, no NVIDIA/Devpost/Twilio task text. The repo is public, so the README's config example uses placeholder logins (`teammate-login`), never real teammates.
- Thread status file format: LAND's, unchanged (`tools/status/README.md`, "Thread status files"). Only the folder moves to `hackathons/events/<slug>/threads/<name>.json`.
- `AGENTS.md` and `STATE.md` do not exist in this repo. So there is no `# Verification scope`, `# Visual rule` or `# Commit format` section. The final check (Task 4) comes from the ticket's **Done when** list. Commit format falls back to `type(scope): summary (refs #98)`, with the session's `Co-Authored-By` trailer.
- Visual rule: see gate 1 decision D3. The plan copies LAND's existing page as the reference look and builds no 4-variant page unless the owner asks.

## Gate 1 decisions (most likely to be wrong first)

- **D1. What the build map shows.** LAND's map was 9 hand-picked issues in hardware/hub/software columns. Pick: show **every issue in the repo**, ordered by number, as LAND's node cards in a 3-column grid (1 column under LAND's existing 720px breakpoint). The config has no issue list. This repo has 47 issues, so the demo shows 47 cards. Alternative: columns per assignee, or an optional `map_issues` list in the config.
- **D2. Countdowns and the hand-written task list are dropped.** Both were LAND text in the HTML. The ticket's Done when does not name them. The "Needs you" section keeps the generic parts: unpushed `issue-*` branches with their push command, "main is behind", and blocked or needs-owner threads. Alternative: a `deadlines` list in the config drives the countdowns.
- **D3. No 4-variant page.** The ticket says copy LAND's page, and its look is the reference. The only new layout is the D1 grid and the teammate sections, built from LAND's existing CSS. If the owner wants variants of the map, a Task 0 adds them before Task 2.
- **D4. Config is a file, not flags.** The only argument is the event slug (plus LAND's `--once`). `repo`, `checkout` and `port` are required. `teammates` is optional and defaults to `[]`. `checkout` is new: the collector runs `git` in the event repo's local clone, and LAND got that path from its own location.
- **D5. Times show in the browser's own time zone.** LAND fixed `America/Chicago`.

## Review Focus

1. Missing or broken `status-config.json`, or a missing required key: the collector exits non-zero before it starts serving. Its stderr names the config path and the missing key. It must not serve an empty page. (Task 1, Step 4.)
2. An unreadable thread file (half-written or bad JSON) shows as a `blocked` thread with "Unreadable status file". LAND did this; keep it. (Task 4 demo, second thread file.)
3. A `GET /status.json?t=123` (the page adds a cache-buster query) must serve the event folder's file, not 404. (Task 2, Step 3.)
4. A request for any path other than `/`, `/index.html` and `/status.json` must not serve files from the event folder. Config holds teammate logins. (Task 2, Step 3.)
5. A teammate's `git` pattern matches commit author name or email case-insensitively, the way LAND's `RAFAEL_GIT` did. A teammate with no matching activity shows "Nothing from <login> yet." and does not hide the section. (Task 4 demo, `no-activity-login`.)

### Task 1: Collector reads the event config and writes into the event folder

**Files:**
- Create: `hackathons/agent/status/collector.py` (start from a copy of `tools/status/collector.py`)

**Interfaces:**
- Produces: CLI `collector.py SLUG [--once]`. With `--once` it writes `status.json` once, prints the `errors` list as JSON and exits 0, like LAND.
- Produces: `status.json` keys: all of LAND's keys except `rafael`, plus `"event": SLUG`, `"checkout": <abs path>`, `"teammates": [{"github": str, "events": [...]}]`. Each event has LAND's `rafael` entry shape (`time`, `kind`, `text`, `url`), at most 30 per teammate, newest first.
- Produces: `map` keyed by every issue number from `collect_issues()`, with LAND's node shape and states (`not-started`, `working`, `blocked`, `pr`, `merged`).

Config file `hackathons/events/<slug>/status-config.json`:

```json
{
  "repo": "owner/name",
  "checkout": "~/Developer/name",
  "port": 8100,
  "teammates": [{"github": "teammate-login", "git": "teammate|their-email-user"}]
}
```

- [ ] **Step 1: Copy LAND's collector.** `cp tools/status/collector.py hackathons/agent/status/collector.py`. Verify: `git diff --stat -- tools/status` prints nothing.

- [ ] **Step 2: Replace the constants with config.** Remove `REPO`, `GH_REPO`, `RAFAEL_LOGIN`, `RAFAEL_GIT`, `PORT`, `MAP_ISSUES`. Add `load_config(slug: str) -> dict`. It reads `<events dir>/<slug>/status-config.json`, where the events dir is `os.path.join(HERE, "..", "..", "events")` and `HERE` is the script's real path (`os.path.realpath`), the same rule `/hack-prep` uses. It expands `~` in `checkout` and compiles each teammate's `git` with `re.I`. When the file or a key is missing, it raises `SystemExit` with a one-line message that names the path and the key. Set the module globals `GH_REPO`, `CHECKOUT`, `EVENT_DIR`, `PORT`, `TEAMMATES` once at startup. `run()` keeps its `cwd` default, now `CHECKOUT`. Parse arguments with `argparse` (`slug`, `--once`).

- [ ] **Step 3: Generalize the collect functions.**
  - `collect_threads()` globs `os.path.join(EVENT_DIR, "threads", "*.json")`. On startup the collector runs `os.makedirs(<EVENT_DIR>/threads, exist_ok=True)`.
  - `build_map(...)` loops over every issue in `issues` instead of `MAP_ISSUES`. The state rules stay as they are.
  - In `collect()`, the `rafael` block becomes one entry per teammate with the same two filters (git pattern on pushes, GitHub login on issue comments). Add `event` and `checkout` to the returned dict.
  - `write_status()` writes `status.json.tmp` and `status.json` into `EVENT_DIR`.
  - Change the module docstring to name the new start command. Leave every other function as it is.
