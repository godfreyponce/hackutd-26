# Win agent: /hack-prep winner bar Implementation Plan (issue #93)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After it writes the rules card, `/hack-prep` also writes `hackathons/events/<slug>/winner-bar.md`. The file holds numbers measured from the reference winner's public winning Devpost pages: write-up words (range and median), video length, repo link, and tracks listed. Each number links to its pages, and the video target is capped by the rules card.

**Architecture:** One new stdlib Python script, `winner-facts.py`, does all the measuring, so the numbers can be rerun instead of being counted by eye. It reads the Devpost profile, finds the winning projects in the profile's JSON-LD, fetches each project page with curl, gets each video's length with `yt-dlp --skip-download`, and prints two markdown tables. `SKILL.md` gets new steps that run the script, read the video max from the rules card it just wrote, and fill a new committed template.

**Tech Stack:** Markdown skill for Claude Code, python3 stdlib, curl, yt-dlp (all installed; no new dependency).

**Spec:** `~/Developer/docs/superpowers/specs/2026-11-09-hackathon-win-agent-design.md` and issue #93 (`gh issue view 93`). The #91 plan (`git show main:docs/superpowers/plans/2026-11-09-issue-91.md`) set the patterns this plan reuses: the curl User-Agent, the install link, and the demo through a fresh `claude -p`.

## Gate 1 decisions (most likely to be wrong first)

1. **What "tracks are listed" measures.** Devpost shows only the prizes a project *won* under "Submitted to". It does not show tracks a project opted into and lost. So on a winning page this count is always at least 1, and it cannot tell a listed track from an unlisted one. The plan measures "prizes shown under Submitted to" and says so in the bar. The other choice: count whether the write-up text names the prize or sponsor. That choice is fuzzier (name matching) and adds code. Pick: the Submitted-to count.
2. **The Devpost user name `adamFabsa` is written in the committed `SKILL.md`.** The issue and spec are already public and name him, and the bar stays in the gitignored folder. The other choice: the skill reads the name from a gitignored file such as `hackathons/events/winner-ref.txt`. Pick: name it in `SKILL.md`, with no word about him being a teammate.
3. **Video target when the rules card has no video max.** The plan writes "not set: the rules card has no video max" and shows Adam's range and median as reference only. It does not use his median as the target, because video length must come from the rules card. When a max exists, the target is the smaller of Adam's median and the rules max, and the hard limit is the rules max.
4. **Write-up target.** The bar gives a floor (Adam's shortest) and an aim (Adam's median). `/hack-check` and `/hack-submit` decide pass or fail later.

### Task 1: `winner-facts.py`, the measuring script

**Files:**
- Create: `hackathons/agent/skills/hack-prep/winner-facts.py`

**Interfaces:**
- Produces: `python3 -I winner-facts.py <devpost user>`. GET and `yt-dlp --skip-download` only. Exit 0 prints two markdown tables to stdout (formats below). Exit 1 with one stderr line when the profile fetch fails or the profile has no winning projects. Exit 2 on a wrong argument count.
- Fetches use `subprocess.run(["curl", "-fsSL", "--max-time", "30", "-A", UA, url])`, the same User-Agent string and the same labeled-guess 30 s timeout as `page-text.sh`. Do not use urllib: curl with this UA is the path proven against Devpost.
- Functions (module level, so Step 5 can import them):
  - `winning_projects(profile_html: str) -> list[tuple[str, list[str]]]`: (project url, award strings) from the JSON-LD blocks that have a non-empty `"award"`, in page order.
  - `write_up_words(page_html: str) -> int`: visible text after the first `</ul>` that follows `data-slick="true"` inside `id="gallery"`, up to `id="built-with"`. If there is no gallery, start at `id="app-details-left"`. Strip `<script>`/`<style>`, then tags, then unescape entities. A word is a whitespace-separated token that contains at least one letter or digit (`re.search(r"\w", tok)`), so emoji-only tokens do not count.
  - `video_url(page_html: str) -> str | None`: the first `youtube.com/embed/<id>` in the gallery, as `https://www.youtube.com/watch?v=<id>`, or the first `player.vimeo.com/video/<id>`, as `https://vimeo.com/<id>`. Otherwise None.
  - `video_seconds(url: str) -> int | str`: runs `yt-dlp --skip-download --print duration <url>`. Returns int seconds, or `"unknown (yt-dlp exit N)"`.
  - `repo_place(page_html: str) -> str`: `"Try it out"` if a `https://github.com/` or `https://gitlab.com/` link is in the Try it out section. Otherwise `"write-up"` if one is in the write-up, `"updates only"` if one is in Updates, `"no"` if none.
  - `prizes(page_html: str) -> list[str]`: the prize text of each `<li>` in `id="submissions"` that has the `winner label` span.
- stdout format (exact headings; Task 2's template places these tables; `{…}` marks values the script fills):

```markdown
### Pages measured
| # | Project | Prizes shown under Submitted to | Write-up words | Video | Repo link |
|---|---|---|---|---|---|
| [1](https://devpost.com/software/lantern-8o9akp) | Aegis | Spacetime Track (HackUTD 2026: ZeroDay) | {words} | [2:30](https://www.youtube.com/watch?v=lORYwjN39mg) | updates only |

### Measured
| Measure | Value | From |
|---|---|---|
| Write-up words | range {min} to {max}, median {median} ({k} of {n} pages) | [1](url) [2](url) ... |
| Video length | range {m:ss} to {m:ss}, median {m:ss} ({k} of {n} pages) | [1](video url) [2](video url) ... |
| Repo in Try it out | {k} of {n} pages | [1](url) ... |
| Prizes shown under Submitted to | {k} of {n} pages (at least 1 prize) | [1](url) ... |
```

  The project name comes from the page `<title>` up to ` | Devpost`. A failed page row reads `fetch failed (exit N)` in the Write-up words cell with the other cells empty. The median of an even count is the mean of the two middle values, rounded half up to a whole word or second. Durations print as `m:ss`. "From" lists only the pages that gave a value for that row.
