# Win agent: /hack-prep rules card + install Implementation Plan (issue #91)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/hack-prep <devpost url>` reads an event's public Devpost pages plus hand-pasted rules and writes `hackathons/events/<slug>/rules-card.md`, where every item has a source and a missing rule is written as "not found". An install script makes `hack-*` skills work from any repo.

**Architecture:** One skill folder (`SKILL.md` + a small `page-text.sh` fetch helper) and one committed template, both under `hackathons/agent/`. `install.sh` symlinks each skill folder into `~/.claude/skills/`, which is `~/Developer/skillbook/skills/`. Skillbook ignores the links with one `.gitignore` line. The skill finds the events folder through its own real path, so cards always land in the gitignored `hackathons/events/` of the checkout the link points at.

**Tech Stack:** Markdown skill for Claude Code, bash, curl, python3 stdlib (already installed; no new dependency).

**Spec:** `~/Developer/docs/superpowers/specs/2026-11-09-hackathon-win-agent-design.md` and issue #91 (`gh issue view 91`). This plan covers only the rules card and the install. The sponsor brief, the targets and the winner bar are later tickets.

## Global Constraints

- Outside sites are read-only. The agent never posts, comments, messages or submits on Devpost, Discord, GitHub or anywhere else. The helper only does HTTP GET.
- Per-event material stays in `hackathons/events/<slug>/` (gitignored). The repo is public; nothing about strategy, scouting or teammates goes in `hackathons/agent/`.
- Video length always comes from the event's rules card, never a fixed number. No duration number appears in `SKILL.md` or the template.
- No new dependency. curl, python3, `gh`, `ffprobe` and `yt-dlp` are already available.
- The skillbook edit is one `.gitignore` line only. Do not commit in skillbook; tell the owner.
- Templates for the rules card live in `hackathons/agent/` (committed); filled cards live only in the event folder.
- `AGENTS.md` and `STATE.md` do not exist in this repo, so there is no `# Verification scope`, `# Visual rule` or `# Commit format` section. Commit format falls back to `type(scope): summary (refs #91)`, with the session's `Co-Authored-By` trailer. The final check (Task 4) is built from the ticket's **Done when** list.
- Not visual: the output is a markdown card, so the 4-variant rule does not apply.

## Review Focus

1. A URL that is not `https://<slug>.devpost.com/...` (e.g. `devpost.com/software/x`, an MLH page): the skill stops and asks for the event's Devpost URL. It does not invent a slug. (Pinned in Task 3, SKILL.md step 1.)
2. Devpost refuses a page (403, 404, timeout): `page-text.sh` exits non-zero, and the card lists that page under "Sources" as `fetch failed (exit N)`. Rules that only that page would hold become "not found". (Task 2 test for the exit code; Task 3 step 3.)
3. No `pasted/` folder, or an empty one: not an error. The skill creates the folder, and the card's Sources section says `pasted/: no files`. (Task 3 step 2.)
4. A video rule given as a range ("45 sec - 1 min"): the max is the upper end, and the verbatim quote sits beside it. (Task 3 step 4; the demo checks it.)
5. `~/.claude/skills/hack-prep` already exists as a real folder (not a link): `install.sh` refuses with a message and exits 1. It never deletes it. A link that already points elsewhere (e.g. at a removed worktree) is repointed. (Task 1 tests, run under a temp `HOME`.)

### Task 2: Page-text helper and rules-card template

**Files:**
- Create: `hackathons/agent/skills/hack-prep/page-text.sh` (executable)
- Create: `hackathons/agent/templates/rules-card.md`

**Interfaces:**
- Produces: `page-text.sh <url>`. It prints the page's visible text to stdout, one block per line, and exits non-zero when the fetch fails (HTTP 4xx/5xx or network error). It only does GET.
- Produces: the template's section headings and placeholders, which Task 3's SKILL.md tells the agent to fill.

- [ ] **Step 1: Write `page-text.sh`.** `set -euo pipefail`. `curl -fsSL --max-time 30 -A "<Safari UA string>" "$1"` piped into `python3 -I -c '...'` (stdlib `re` and `html` only). The python drops `<script>`/`<style>` blocks, turns `<br>` and closing `p, li, h1-h6, div, tr` tags into newlines, strips other tags, unescapes entities, collapses spaces, and drops blank lines. The 30 s timeout is a guess, labeled so in a comment. `pipefail` carries curl's failure out as the exit code.

- [ ] **Step 2: Test it.**


### Task 3: The /hack-prep skill

**Files:**
- Modify (replace the placeholder): `hackathons/agent/skills/hack-prep/SKILL.md`

**Interfaces:**
- Consumes: `page-text.sh <url>` and the template headings (Task 2); the link made by `install.sh` (Task 1).
- Produces: `hackathons/events/<slug>/rules-card.md` beside the `agent/` folder of the checkout the skill link points at.

- [ ] **Step 1: Write the frontmatter.**

```yaml
---
name: hack-prep
description: Before a hackathon, read the event's Devpost pages and any rules pasted into its event folder, and write a rules card (video max length, required submission fields, tracks and prizes, deadlines) with a source for every item. Use for /hack-prep <devpost url>.
argument-hint: "<devpost url>"
---
```

- [ ] **Step 2: Write the body as numbered steps the agent follows.** Keep it short and in this order:
  1. **Parse the argument.** It must match `https?://<slug>.devpost.com/...`. The slug is the subdomain, and the base is `https://<slug>.devpost.com`. Anything else: stop and ask the owner for the event's Devpost URL (Review Focus 1).
  2. **Find the folders.** Run `realpath` on this skill's base directory. The agent dir is two levels up (`hackathons/agent`), and the event dir is `hackathons/events/<slug>/` beside it. Run `mkdir -p <event dir>/pasted`. Say why in one line: this keeps cards in the gitignored folder whatever repo the command runs from.
  3. **Read the sources.** Run `page-text.sh` on `<base>/`, `<base>/rules` and `<base>/updates`. Record each as `read` or `fetch failed (exit N)`. Do not use WebFetch for Devpost (it returns 403). Do not follow links off Devpost; list them under Not found's "Looked in" if a rule points to them. Read every file in `pasted/`; an empty folder is `pasted/: no files`.
  4. **Fill the template** from `<agent dir>/templates/rules-card.md`. Every row has a verbatim quote and its source (a URL, or `pasted/<file>`). For a range, the rule to follow is the upper end, with the quote beside it.
  5. **Conflicts.** When two sources disagree, add a row with both sources and mark the stricter one under "Follow". Stricter means: the shorter video max, the earlier deadline, the smaller track cap, and for required fields, the union of both lists.
  6. **Not found.** Any of the four items with no source becomes a Not found row listing every source that was read or tried. Never fill it from memory, from Devpost defaults, or from another event.
  7. **Write** `<event dir>/rules-card.md` (overwrite). Reply with its path and the video max line.
  8. **Read-only.** Only GET requests through `page-text.sh`. Never log in, post, comment, message or submit anywhere.
