# Win agent: /hack-submit pass/fail audit Implementation Plan (issue #94)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/hack-submit <slug>` reads the Devpost draft the owner pasted into `hackathons/events/<slug>/submission-draft.md`, checks it, the linked repo and the video against `rules-card.md` and `winner-bar.md`, then prints a pass/fail table and writes the same table to `submit-audit.md`. It never submits.

**Architecture:** One new markdown skill, `hackathons/agent/skills/hack-submit/SKILL.md`, and two committed templates. One is a blank paste form with `=== Field ===` marker lines, so a shell one-liner can cut out each field. The other is the audit table. Every number in the table (word count, video seconds, repo visibility) comes from a command: `awk`/`grep`, `ffprobe`, `yt-dlp`, `gh`. The model does not count anything by eye. The skill finds the event folder through its own real path, the same way as `/hack-prep` and `/hack-coord`.

**Tech Stack:** Markdown skill for Claude Code, bash, `gh`, `ffprobe`, `yt-dlp` (all installed; no new dependency).

**Spec:** `~/Developer/docs/superpowers/specs/2026-11-09-hackathon-win-agent-design.md` and issue #94 (`gh issue view 94`). Blockers #91 and #93 are closed. The #93 plan (`docs/superpowers/plans/2026-11-09-issue-93.md`) set the patterns reused here: the install link, the fixed-number grep, and the demo through a fresh `claude -p`.

## Global Constraints

- Outside sites are read-only. The agent never posts, comments, messages or submits on Devpost, Discord, GitHub or anywhere else. The only `gh` calls are `gh repo view` and `gh api` GETs with no `-X`, `-f` or `-F`.
- Never submits and never edits the Devpost draft or `submission-draft.md`. It only reports.
- Per-event material stays in `hackathons/events/<slug>/` (gitignored). The repo is public. Nothing about strategy, scouting or teammates goes in `hackathons/agent/`. The demo draft lives only in the event folder.
- Video length always comes from the event's rules card, never a fixed number. No duration number appears in `SKILL.md` or either template.
- No new dependency. `gh`, `ffprobe` and `yt-dlp` are already available.
- It must work when `targets.md`, `kickoff.md` or `check-log.md` is missing. It skips those rows and lists them under Skipped.
- `AGENTS.md` and `STATE.md` do not exist in this repo, so there is no `# Verification scope`, `# Visual rule` or `# Commit format` section. Commits use the fallback `type(scope): summary (refs #94)` with the session's `Co-Authored-By` trailer. The final check (Task 3) is built from the ticket's **Done when** list, as in #91 and #93.
- Not visual: the output is a markdown table, so the 4-variant rule does not apply.

## Gate 1 decisions (most likely to be wrong first)

1. **What "every track in the rules card is listed in the draft" means.** Read literally, it fails every real draft. The HackAI 2026 card lists 18 tracks with a cap of two sponsor tracks, and some tracks (Best Beginner, Best Solo) do not fit every team. The plan checks three things instead:
   - one row per `targets.md` prize, which must be listed;
   - "Tracks listed": the draft lists at least one track;
   - "Track cap": the tracks that count toward the cap are no more than the cap.

   Under the table, one line names the rules-card tracks the draft did not opt into, so the owner can scan them. That line is not pass/fail. The other choice is the literal reading: one fail row per unlisted track. Pick: the three checks.
2. **A third result, `by hand`.** Some rules-card fields cannot be proved from a pasted draft, for example "commits only inside the hacking window" or "no idea reused". The ticket says pass or fail. The plan adds `by hand` for these and counts them apart from fails, so 2 rules the agent cannot check do not hide the real fails. The other choice: mark them `fail` with the fix "check by hand". Pick: `by hand`.
3. **The paste form.** The owner copies a committed blank form, `templates/submission-draft.md`, and pastes each Devpost field under its `=== Field ===` line. Devpost write-ups hold their own `## Inspiration`-style headings, so the form cannot use markdown headings as field markers. This adds a third file the ticket did not name. The other choice: a free paste, and the model finds the fields. Then the word count is not a command. Pick: the form. When the draft is missing, the skill prints the `cp` command and the field list and stops. It does not copy the form itself.
4. **Which repo is checked.** Only the first `github.com/<owner>/<repo>` link in the draft (Try it out first, then any field). With no link, the exists, public and README rows fail with "no repo link in the draft". The skill does not fall back to the repo of the folder it runs in.

If every field is empty, start the reply with "the draft looks empty: paste each field under its line" and go on (every draft row fails).
  5. **Repo.** The repo is the first `https://github.com/<owner>/<repo>` in Try it out links, else the first in any field. Strip `.git` and any deeper path. Rows:
     - Repo linked in draft (`gh`): pass when a repo was found. Draft-has names the field it was in.
     - Repo exists (`gh`): `gh repo view <owner>/<repo> --json nameWithOwner,visibility,url` exits 0.
     - Repo is public (`gh`): `visibility` is `PUBLIC`.

     With no repo found, the last three rows fail with "no repo link in the draft".
  6. **Video.** Read the Video demo link field.
     - A local path: run `ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 <path>`.
     - A YouTube or Vimeo URL: run `yt-dlp --print duration --skip-download "<url>"`.
     - Non-zero exit, `NA`, other host: ask the owner to type the length as m:ss and stop. Go on with the answer, marked `(owner typed)`.
     - Empty field: no length. The video rows fail with "no video link in the draft".

The fix says how much to cut or add. When video max is under Not found, the row is `by hand`. Never use a number that is not on the card.

     - the video row from step 6;

     - Deadlines: one row for the submission close. Pass when `date` is before it, and Draft-has shows the time left.
     - Each other Not found item: a `by hand` row that names it.
  8. **Winner-bar rows**, one per Bar row:
     - Write-up words: pass at or above the floor. The fix gives the words needed to reach the floor and the aim.
     - Video length: pass at or under the aim. A fail here is a bar miss, not a rule break.
     - Repo linked in Try it out: pass when the repo was found in Try it out links.
     - Tracks listed: pass when at least one track is opted into.
  9. **Optional rows.**
     - `targets.md`: one row per target prize. Pass when the opted-in tracks name it.
     - `kickoff.md`: one row per item of its integration bar. Pass when the write-up names that sponsor API or call.
     - `check-log.md`: one row for its last line. Pass when the line has no `fix-now`.
  10. **Write.** Fill `templates/submit-audit.md` with every row, the not-opted-into line, Skipped and the counts. Write `<event dir>/submit-audit.md`, overwriting it. Print the same Result line and Audit table in the reply, then the fails in order with their fixes.
  11. **Read-only.** Only `gh repo view`, `gh api` GETs, `ffprobe`, `yt-dlp --skip-download`, `date`, and file reads in the event dir. Never log in, post, comment, message or submit anywhere. Never edit `submission-draft.md`.
