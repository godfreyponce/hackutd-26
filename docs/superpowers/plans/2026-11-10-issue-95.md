# Win agent: /hack-kickoff idea check + real-integration bar Implementation Plan (issue #95)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/hack-kickoff <slug> [idea text]` checks a picked idea against `targets.md` and `sponsor-brief.md` and writes `hackathons/events/<slug>/kickoff.md`. That file holds a fits-or-misses verdict with a reason for each target prize and each other sponsor prize, and a checkable "real integration" bar. The bar lists the sponsor API calls in the core user path, the real data they use, and what counts as faked. `/hack-check` (#96) holds the team to that bar later.

**Architecture:** One prose skill (`hackathons/agent/skills/hack-kickoff/SKILL.md`) and one committed template (`hackathons/agent/templates/kickoff.md`). No new script. The skill reuses `/hack-prep`'s helpers by path: `skills/hack-prep/page-text.sh` reads a docs page, and `skills/hack-prep/save-output.sh` writes `kickoff.md` so that a rerun keeps the owner's hand edits. `install.sh` already links every folder in `hackathons/agent/skills/`, so it needs no change.

**Tech Stack:** Markdown skill for Claude Code, bash, `gh` (all already installed, so no new dependency).

**Spec:** issue #95 (`gh issue view 95`) and `~/Developer/docs/superpowers/specs/2026-11-09-hackathon-win-agent-design.md` (the `/hack-kickoff` line). It builds on #92's outputs (`templates/sponsor-brief.md`, `templates/targets.md`, `save-output.sh`). Blocker #92 is closed.

## Decisions for gate 1 (most likely to be wrong first)

1. **The check covers every sponsor prize in the brief, not only the 1 or 2 targets.** `kickoff.md` has a Targets table and an "Other sponsor prizes" table. Reason: the demo must flag that Nessie is not in Nudge's core path. In #92's th26 demo, with the demo `team.md`, the targets were Gemini and ElevenLabs, not Capital One. A targets-only check would then say nothing about Nessie. The integration bar is still written only for the target prizes that the idea fits.
2. **Two verdicts only: `fits` or `misses`.** `fits` means that the idea as written already has the sponsor tool in its core path (the demo cannot run without it). `misses` means that it does not. Each `misses` row has a "To fit" cell: one change that would put the tool in the core path, or `none: <why>` when the tool cannot carry this idea. There is no third verdict for "fits after a change". The ticket asks for fits and misses.
3. **The argument form is `/hack-kickoff <slug> [idea text]`.** The slug works as it does in `/hack-coord`. Idea text in the argument wins over `idea.md`, and `kickoff.md` notes which one was used. A Devpost project URL is not read as an idea source. For the demo, `idea.md` is pasted from Nudge's Devpost page.
4. **API call names come only from a page that was read.** Sources are the brief's Docs rows, the docs link read with `page-text.sh`, or a sponsor GitHub org README read with `gh`. If no call name is found, the bar item says `API call: not found (looked in <links>); name it before building` and names the user step anyway. Evidence that call names can be found: `gh api repos/nessieisreal/nessie-javascript-sdk/readme` names `getAllAccounts()`.
5. **A rerun goes through `save-output.sh`, so a hand-edited `kickoff.md` is kept** and the new version goes to `kickoff.new.md`. To check a changed idea, the owner deletes `kickoff.md` (or leaves it unedited) and reruns.

- [ ] **Step 2: Body.** It opens with one paragraph: "Check one picked idea against the event's prizes and set the bar that `/hack-check` holds the team to. Every verdict quotes the idea and the brief. A call or fact you cannot find is written as not found, never guessed." Then these steps, in order:
  1. **Parse.** The first word is the slug. It must match `^[a-z0-9][a-z0-9-]*$`. For anything else (a URL, a path, nothing), stop and ask the owner for the event slug, the folder name under `hackathons/events/`. The rest of the argument, if any, is the idea text.
  2. **Find the folders and the idea.** Run `realpath` on this skill's base directory. The agent dir is two levels up from it. The event dir is `hackathons/events/<slug>/`, beside the agent dir. The idea is the argument text. If there is none, it is `<event dir>/idea.md`. If both are present, use the argument and note it in "Idea from". If neither is present, stop, write nothing, and ask the owner to give the idea as text after the slug or to paste it into `<event dir>/idea.md`.
  3. **Read the inputs.** Read `<event dir>/targets.md` and `<event dir>/sponsor-brief.md`, never their `.new.md` files. If either one is missing, stop, write nothing, and tell the owner to run `/hack-prep <devpost url>` first (targets also need `team.md`). A `targets.md` that says no sponsor prize meets the bar is not missing: it has no targets. Read `<event dir>/rules-card.md` if it exists, for the sponsor track cap only.
  4. **Core path.** From the idea text, write down its core user path: the steps that the demo cannot run without, and where each step gets its data. Quote the idea for each step. This is what every verdict is measured against.
  5. **Verdict per prize.** For each target in `targets.md`, then each other sponsor prize section in `sponsor-brief.md`, decide one of the following:
     - `fits`: the idea as written has that prize's tool in a core path step.
     - `misses`: it does not. That includes a tool used only as a side feature, and an idea whose data comes from elsewhere (its own database, manual entry, a hardcoded list) when the tool could supply it.
     The reason is one line and quotes both the idea and the brief's Tool row. Every `misses` row has a "To fit" cell: one change that puts the tool in a core path step, or `none: <why>` when the tool cannot carry this idea.
  6. **Verdict line.** If the idea fits at least one target, write `Fits target <n>, <prize>.`, listing each target it fits. If it fits none, write `Fits no target.` and the single change most likely to fix that, taken from a target's To fit cell. A sponsor prize outside `targets.md` that the idea fits goes in the line too, as "also fits <prize> (not a target)".
  7. **Integration bar.** Write one bar block for each target the idea fits. If it fits none, the section is one line: `No bar set: the idea fits no target. Pick a change from To fit, update the idea, and rerun /hack-kickoff.` For each block:
     - **Core path call.** Name the user step and the sponsor API call it runs. Take the call name only from a page that you read: the brief's Docs link read with `<agent dir>/skills/hack-prep/page-text.sh`, WebFetch once when that returns little more than the title, or the public READMEs of the sponsor's GitHub org read with `gh`. If no page names a call, write `API call: not found (looked in <links>); name it before building` and add a Not found row.
     - **Real data.** Name the data that the call reads or writes, and where it comes from (for example a sponsor sandbox account created through the API, or the user's own input sent to the API). Write it with the source of how to get that data.
     - **Counts as faked.** List what fails the bar: hardcoded or recorded responses in place of the call, a mock server, a call made only in a script that the demo does not reach, the tool named only in the write-up or slides, and any fake that is specific to this idea.
  8. **Write.** Copy `<agent dir>/templates/kickoff.md`, fill it, and write it to `<event dir>/.drafts/kickoff.md` (`mkdir -p <event dir>/.drafts`). Run `<agent dir>/skills/hack-prep/save-output.sh <event dir>/.drafts/kickoff.md <event dir>/kickoff.md`. Never write `kickoff.md` directly. Reply with the line that the script printed, the Verdict line, and the first item of each bar block.
  9. **Read-only.** Send only GET requests: `page-text.sh`, WebFetch, and `gh` reads. Never log in, post, comment, message or submit anywhere.
